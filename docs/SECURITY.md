# Secrets handling and audit

## Where each secret lives

| Secret | Used for | Local | Render |
|---|---|---|---|
| `DB_PASSWORD` | PostgreSQL login | `backend/.env` | generated by Render, wired by `render.yaml` |
| `JWT_SECRET` (32+ characters) | Signing login tokens | `backend/.env` | service environment |
| `TOKEN_ENCRYPTION_KEY` (base64, 32 bytes) | AES-256-GCM encryption of Gmail tokens stored in `gmail_connections` | `backend/.env` | service environment |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | Gmail OAuth | `backend/.env` | service environment |
| `GEMINI_API_KEY` | Email extraction | `backend/.env` | service environment |

Rules:
- `application.yml` has no secret defaults. `DB_PASSWORD`, `JWT_SECRET` and `TOKEN_ENCRYPTION_KEY` have no default at all, and the app refuses to start if `JWT_SECRET` is shorter than 32 characters or `TOKEN_ENCRYPTION_KEY` is not base64 of 32 bytes. The Google and Gemini values default to empty, which switches those features off.
- `.gitignore` excludes `.env*` everywhere except `.env.example` files, which contain placeholders only.
- Every `.env` line must be `NAME=value`. OS environment variables override `.env`.
- `VITE_*` variables are compiled into the browser bundle. They must never hold a secret.
- User passwords are stored as BCrypt hashes. Gmail tokens are stored encrypted. Logs record only the exception type or HTTP status for token failures, never the token.

## If a secret leaks

Rotate it, then redeploy. Deleting it from git history is not enough.

| Secret | What to do | Effect |
|---|---|---|
| `GOOGLE_CLIENT_SECRET` | Reset it in Google Cloud Console | Gmail connect and refresh fail until the new value is deployed |
| `GEMINI_API_KEY` | Create a new key, delete the old one | None once deployed |
| `JWT_SECRET` | Set a new value | Everyone is logged out |
| `TOKEN_ENCRYPTION_KEY` | Set a new value, then clear `gmail_connections` | Every user must reconnect Gmail (old tokens can no longer be decrypted) |
| `DB_PASSWORD` | Reset it in the database settings | Redeploy so the service picks it up |

## Audit, 20 October 2026

Scanned the repository contents (backend, frontend, docs, CI, SQL):
- No API keys, OAuth secrets, private keys or tokens found, and no secret-shaped strings.
- No secret defaults in `application.yml`.
- The only passwords in the repo are the throwaway `postgres` password of the CI database container and the documented demo account password in `db/demo_seed.sql` (stored there as a hash). Neither is a real credential. The demo seed must never be loaded into the deployed database.
- The root `.env.example` listed bare names without values. Copied to `.env` it made the app crash at startup (`Malformed entry`). It was removed; `backend/.env.example` is the only template.

Git history is checked separately with the commands in the final-audit commit notes.
